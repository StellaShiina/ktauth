03UNDER THE HOOD

小体积，不是小能力

在一道门后，
做足关键判断。

A / 01

IP 策略缓存

白、灰、黑名单覆盖单个 IPv4 与 IPv6 /64；Redis 缓存让入口判断保持迅速。

A / 02

毫秒级滑动窗口

Redis Lua 与 Sorted Set 原子计算请求窗口，精确控制突发流量与持续滥用。

A / 03
JWTSESSION / REDIS

完整身份闭环

邀请码或邮箱验证码注册，bcrypt 密码哈希，JWT 与可撤销 Redis 会话协作。

A / 04
HANDLER→SERVICE→REPOSITORY→DB

干净的 Go 内核

Gin 驱动的分层架构，PostgreSQL 持久化，Redis 承担高速状态；边界明确，便于阅读与扩展。

04REFERENCE

需要时，再深入

API，保持
简洁可查。

这里只列出接口与职责。请求结构和完整技术细节请前往 GitHub 文档。

用户 / USERS

  • POST/api/users/register邀请码或邮箱注册
  • POST/api/users/send-code发送邮箱验证码
  • POST/api/users/verify-code验证并消费验证码
  • POST/api/users/login用户登录
  • GET/api/users/auth检查登录状态
  • GET/api/users/logout结束当前会话
  • GET/api/users用户列表 · 管理员

令牌 / TOKENS

  • GET/api/tokens/restock批量生成邀请码
  • DELETE/api/tokens/flush清空可用邀请码
  • GET/api/tokens获取一个邀请码
  • GET/api/tokens/all全部邀请码

策略 / IP RULES

  • GET/api/ips列出 IP 规则
  • POST/api/ips/new创建 IP 规则
  • DELETE/api/ips删除 IP 规则
